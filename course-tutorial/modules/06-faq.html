找 Bug：哪一行会导致 tags/前端 出现双重 URL 编码？

这是 v2.0 修复前的 tagToSlug 早期实现，故意留了一个 bug。点你认为有问题的那一行：

Bug 定位 · tag → slug 转换

1 export function tagToSlug(name) {
2 const trimmed = name.trim()
3 const lowered = trimmed.toLowerCase()
4 return encodeURIComponent(lowered) // ← 关键行
5 }
✦
v2.0 修复

第 4 行的 encodeURIComponent 是问题根源。VitePress 在生成 URL 路径段时还会再编码一次，导致中文 tag 变成 ai-%E4%B8%8E...。v2.0 改为：return lowered.replace(/\s+/g, '-') —— 空格转连字符，中文直接透传。

8 个高频问题速查表

遇到问题先翻这张表：

Q1 pnpm install 慢 / 失败？ 切到国内镜像：pnpm config set registry https://registry.npmmirror.com。
Q2 如何自定义主题色？ 改 tailwind.config.js 里的 colors.moss，同时改 .vitepress/theme/styles/index.css 里的 --accent。
Q3 如何启用 Giscus 评论？ 5 步：开启 Discussions → 装 giscus App → 建分类 → 拿 ID → 写 .env。详见 docs/COMMENTS.md。
Q4 图片如何优化？ 放原始图到 assets/images/raw/，跑 pnpm images，自动生成 WebP + LQIP 模糊占位。
Q5 如何迁移到别的电脑？ 整个项目就是一份 git 仓库，git clone + pnpm install 三分钟内恢复全部内容。
Q6 RSS 怎么不更新？ pnpm rss 单独跑一次，或 pnpm dev 启动时会自动跑。
Q7 暗色模式怎么定制？ 改 .vitepress/theme/styles/index.css 里的 .dark { ... } 块。
Q8 构建产物在哪里？ .vitepress/dist/。可以整目录 rsync 到任意 Nginx / CDN / 对象存储。

调试心法：3 个"先看这里"

出问题别慌，按顺序查这三处：

01
终端报错信息

VitePress / Vite / TypeScript 的报错通常很具体，复制第一行错误码去搜，比看整页 stack trace 高效得多。

02
浏览器 DevTools Console

前端 JS 错误、404 资源、CORS 问题都会在这里冒出红字。F12 → Console 是 80% 问题的"第二现场"。

03
.vitepress/dist/ 输出

如果 dev 没问题但 build 失败，对比 dist 目录里的 HTML / 资源清单——是否被手动 chunk 拆错了、是否缺了某个依赖。

✦
万能兜底

如果实在搞不定，pnpm post c 清理一次缓存（约等于"重启 VitePress"），大多数怪异问题都会消失。实在不行就 rm -rf node_modules .vitepress/cache && pnpm install。
