## 一 · 创建与编辑

### 1.1 创建新文章草稿

```bash
# 创建带标签的草稿，并自动在编辑器中打开
pnpm post n ai-agent-design --draft -t "AI,Agent" -o
```

**参数说明：**

| 参数 | 含义 |
| --- | --- |
| `n` (`new`) | 创建新文章 |
| `ai-agent-design` | 文件名（slug），小写字母 / 数字 / 连字符 |
| `--draft` | 标记为草稿（构建时不会出现在列表） |
| `-t "AI,Agent"` | 标签，逗号或空格分隔 |
| `-o` (`--open`) | 创建后用 VS Code 打开文件 |

### 1.2 完整字段示例

```bash
pnpm post n vue3-reactivity \
  -T "Vue 3 响应式原理" \
  -d "从 Proxy 拦截到 effect 调度" \
  -a "窦长友" \
  -c "前端框架" \
  -t "Vue3,响应式,源码" \
  -C "/assets/vue3-cover.png" \
  -D 2026-06-22 \
  --draft \
  -o
```

### 1.3 编辑完成并发布

```bash
# 发布（移除 draft 标记，更新日期）
pnpm post p ai-agent-design -y
```

**参数说明：**

| 参数 | 含义 |
| --- | --- |
| `p` (`publish`) | 发布草稿 |
| `-y` (`--yes`) | 跳过确认 |
| `-D 2026-06-22` | 可选：自定义发布日期 |

### 1.4 frontmatter 顺序约定

`pnpm post new` 写入与解析均遵循以下顺序：

```yaml
---
title: 文章标题              # 必填
description: 文章摘要         # 可空
date: 2026-06-22             # 默认 today
updated: 2026-06-22          # 可空
author: 窦长友                # 可空
category: 前端工程           # 可空
tags:                       # 可空
  - VitePress
  - 性能优化
cover: /images/xxx.webp      # 可空
draft: false                 # 默认 false
---
```

## 二 · 元数据管理

### 2.1 查看所有文章

```bash
# 表格输出（含字数、阅读时长）
pnpm post l

# 包含草稿
pnpm post l --draft

# 按标签过滤
pnpm post l --tag Vue3

# JSON 输出（适合管道）
pnpm post l --json
```

### 2.2 查看单篇文章

```bash
# 查看 frontmatter 与正文前 10 行
pnpm post r ai-agent-design
```

### 2.3 更新元数据

```bash
# 更新标题
pnpm post u ai-agent-design -T "AI Agent 设计模式" -y

# 追加标签（保留原有并去重）
pnpm post u ai-agent-design --append-tags "工程化" -y

# 移除指定标签
pnpm post u ai-agent-design --remove-tag "演示" -y

# 替换为指定列表
pnpm post u ai-agent-design --tags "AI,Agent,设计模式" -y

# 切换草稿 / 正式
pnpm post u ai-agent-design --no-draft -y
pnpm post u ai-agent-design --draft -y
```

写入前会打印 diff 预览；非 `-y` 模式需要确认一次。

## 三 · 本地预览

### 3.1 启动开发服务器

```bash
# 默认启动（http://localhost:5173）
pnpm post s

# 全局可访问 + 自动打开浏览器
pnpm post s --host --open

# 指定端口
pnpm post s --port 8080

# 启动前先生成 RSS
pnpm post s --rss
```

**说明**：VitePress HMR 监听 `content/posts/` 目录，文章保存后**无需重启 dev server**。

### 3.2 预览生产构建产物

```bash
# 完整构建
pnpm build

# 本地预览 dist
pnpm preview --host 0.0.0.0
```

> `pnpm preview` 是构建后的静态文件预览，**无 HMR**，改文章需重新 `pnpm build`。

### 3.3 清理构建缓存

```bash
pnpm post c
```

清理 `.vitepress/cache` 与 `.vitepress/dist`，再启动/构建可避免脏数据：

```bash
pnpm post c && pnpm post s
pnpm post c && pnpm build
```

## 四 · 🆕 一键部署到 GitHub Pages

> 源码：[`scripts/post-cli/deploy.mjs`](../scripts/post-cli/deploy.mjs) · 完整文档：[`scripts/readme.md` § 5.5](../scripts/readme.md)

### 4.1 完整流程

```bash
pnpm post d -y
```

`deploy` 子命令会自动完成：

| 阶段 | 行为 |
| --- | --- |
| **① 预检** | 检查 git 可用、SSH 可达、源码工作区状态 |
| **② 构建** | `npx vitepress build .`（实时透传进度） |
| **③ 推送** | 在 `.vitepress/dist` 内初始化临时仓库 → commit → `force-push` 到 `gh-pages` |
| **④ 清理** | 移除 `.vitepress/dist/.git` 临时仓库 |

### 4.2 常用选项

```bash
# 跳过确认
pnpm post d -y

# 复用现有 .vitepress/dist（不重新构建）
pnpm post d --skip-build

# 只构建不推送（用于本地预览产物）
pnpm post d --skip-push

# 自定义 commit 信息
pnpm post d -m "fix: 更新首页 Banner"

# 推送到指定分支
pnpm post d --branch main

# 推送到指定仓库
pnpm post d --repo git@github.com:OWNER/REPO.git

# 保留 dist/.git（调试）
pnpm post d --no-cleanup
```

### 4.3 环境变量

```bash
# 等价于 --repo / --branch
DEPLOY_REPO=git@github.com:OWNER/REPO.git DEPLOY_BRANCH=main pnpm post d -y
```

### 4.4 部署前置条件

| 条件 | 说明 |
| --- | --- |
| 仓库远端协议 | SSH（默认即可） |
| 本机 SSH 密钥 | `~/.ssh/id_rsa` 已添加到 GitHub Settings → SSH keys |
| GitHub Pages 源 | "Deploy from a branch" · `gh-pages` · `/` |

> **Windows 用户**：`deploy.mjs` 已自动注入 `HOME` 与 `GIT_SSH_COMMAND`，**无需**手动 `$env:HOME = ...`。

### 4.5 部署后验证

```bash
# 等待 1-2 分钟，然后访问：
# https://dcyyd.github.io
# https://dcyyd.github.io/posts/<slug>
```

推送状态检查：

- 仓库 **Insights → Network**：`gh-pages` 分支的 force-push 记录
- 仓库 **Settings → Pages**：最近一次部署时间
- 终端输出末行：`网站将在 1-2 分钟内更新：https://dcyyd.github.io`

## 五 · 端到端工作流示例

### 场景 A：日常发文（推荐）

```bash
# 1. 创建草稿
pnpm post n my-new-article --draft -t "教程,入门" -o

# 2. 在编辑器中撰写内容，保存

# 3. 本地预览
pnpm post s --open

# 4. 追加标签 / 修正元数据
pnpm post u my-new-article --append-tags "TypeScript" -y

# 5. 发布草稿
pnpm post p my-new-article -y

# 6. 一键部署
pnpm post d -y

# 7. 1-2 分钟后访问 https://dcyyd.github.io
```

### 场景 B：紧急修复

```bash
# 1. 编辑 content/posts/<slug>.md，保存

# 2. 不重新构建（复用现有 dist）
pnpm post d --skip-build -m "fix: typo in title" -y

# 3. 等待 1-2 分钟
```

### 场景 C：完全重部署

```bash
# 清缓存 → 构建 → 推送
pnpm post c
pnpm post d -y
```

### 场景 D：多人协作（推荐 Actions）

```bash
# 提交源码（dist 在 .gitignore 中）
git add content/ scripts/ docs/ .vitepress/ package.json
git commit -m "new post: my-new-article"
git push origin main
# GitHub Actions 自动触发 .github/workflows/deploy.yml
```

## 六 · 自动化工作流（GitHub Actions）

### 6.1 工作流文件

工程根 `.github/workflows/deploy.yml` 已内置：

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
  workflow_dispatch:
jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with: { version: 9 }
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: pnpm
      - run: pnpm install
      - run: pnpm build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: .vitepress/dist
      - id: deployment
        uses: actions/deploy-pages@v4
```

### 6.2 首次启用

1. 仓库 → **Settings → Pages** → Source = **GitHub Actions**。
2. **Settings → Actions → General** → Workflow permissions = **Read and write permissions**。
3. 推送 `main` 分支即可。

### 6.3 与 `pnpm post d` 的关系

| 场景 | 推荐方案 |
| --- | --- |
| 日常多人协作 | 推 `main` → Actions 自动部署 |
| 本地调试 / 紧急修复 | `pnpm post d -y` |
| CI 容器 / 沙箱环境 | 依赖 Actions |

两套方案**不冲突**：产物一致，Pages 会渲染最新推送。

## 七 · 常见问题

### 7.1 文章未显示在列表中

| 现象 | 原因 | 修复 |
| --- | --- | --- |
| 列表中找不到 | 仍为 `draft: true` | `pnpm post p <slug> -y` |
| 列表中找不到 | frontmatter 解析失败 | 检查 YAML 缩进与引号 |
| 中文分类页 404 | v2.0 前的老问题 | 升级到 v2.0 后会自动恢复 |

### 7.2 部署失败

参见 [docs/FAQ.md#post-cli-常见错误](FAQ.md#post-cli-常见错误)。

### 7.3 部署后 1-2 分钟仍 404

1. 仓库 **Settings → Pages** 查看部署状态。
2. 强制刷新（`Ctrl + Shift + R`）绕过浏览器缓存。
3. 确认 `gh-pages` 分支存在且 `index.html` 在根目录。

### 7.4 SSH 认证失败

参见 [docs/FAQ.md#ssh-推送失败pnpm-post-d](FAQ.md#ssh-推送失败pnpm-post-d)。

### 7.5 修改了源码但 Pages 没更新

- **方案 A（Actions）**：检查 Actions 日志是否成功。
- **方案 B（pnpm post d）**：是否忘记重新运行 `pnpm post d`。
- 浏览器缓存：强制刷新或使用无痕模式。
