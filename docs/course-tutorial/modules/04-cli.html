Module 04 · CLI 文章管理

post-cli：用一条命令管全部内容

post-cli 是一个零外部依赖的 Node.js 脚本集合（scripts/post-cli/），覆盖创建、更新、发布、列出、查看、部署全流程。学会它，就再也不用手动建文件了。

Quick reference

11 个子命令，一张表速查

所有命令都以 pnpm post <cmd> 触发，且全部有别名（pn、pu、pd …）以减少敲键：

pnpm post n <slug> 创建新文章（new）。必传 slug，-T 标题、-d 摘要、-t 标签、-c 分类、-C 封面图、--draft 草稿。
pnpm post u <slug> 更新 frontmatter。--append-tags 追加标签，--set-category 改分类，-y 跳过确认。
pnpm post p <slug> 把草稿发布上线（draft: true → false）。
pnpm post d [-y] 一键部署：预检 → 构建 → 推送 gh-pages → 清理临时文件。
pnpm post l 列出所有文章（标题、日期、分类、字数、阅读时长）。
pnpm post r <slug> 查看某篇的 frontmatter 与正文摘要。
pnpm post s [--open] 启动 vitepress dev，--open 自动打开浏览器。
pnpm post c 清理 .vitepress/cache、.vitepress/dist、node_modules/.vitepress。
pnpm post help [cmd] 查看所有命令或某个命令的详细帮助。

实战：创建你的第一篇技术文章

假设你要写一篇关于 Vue 3 响应式原理的深度文章：

BASH 

pnpm post n vue3-reactivity-guide \
  -T "Vue 3 响应式原理" \
  -d "从 Proxy 拦截到 effect 调度" \
  -t "Vue3,响应式,源码分析" \
  -c "前端框架"
PLAIN ENGLISH

调用 new 子命令，slug 叫 vue3-reactivity-guide（决定 URL 与文件名）。

-T 设置标题，会写入 frontmatter 的 title 字段。

-d 设置摘要（description），用于列表页和 RSS。

-t 标签列表，逗号分隔，会自动去重。

-c 分类，决定它出现在哪个分类聚合页。

运行后会在 content/posts/vue3-reactivity-guide.md 写入以下骨架：

vue3-reactivity-guide.md 

---
title: Vue 3 响应式原理
description: 从 Proxy 拦截到 effect 调度
date: 2026-06-24
updated: 2026-06-24
author: 窦长友
category: 前端框架
tags:
  - Vue3
  - 响应式
  - 源码分析
cover:
draft: false
---

# 在这里写下你的开篇……
PLAIN ENGLISH

YAML frontmatter：所有元数据。

字段顺序固定，与 scripts/post-cli/frontmatter.mjs 中定义一致。

date 默认填今天（YYYY-MM-DD），后续可手改。

draft: false 表示直接发布，不进草稿区。

下方 --- 之后就是 Markdown 正文。

保存后，浏览器为什么能"自动刷新"？

你在编辑器里改了 .md 文件，浏览器在 0.5 秒内就更新了页面——这背后是 Vite 的 HMR 在工作：

ED
编辑器保存
FS
文件监听
RX
管线重跑
WS
WS 推送
UI
无白屏刷新
点"下一步"追踪 HMR 链路
✦
Practical takeaway

这就是为什么 FilePress Blog 推荐用 post-cli 而不是手动 touch 文件：CLI 写入的字段顺序固定、字段值合法、文件名字符符合 slug 规则——任何不合规都会在前置校验阶段被拦下。

内容约定：哪些字段是必填的？

FilePress Blog 推崇"约定优于配置"——大部分字段都可以省略，系统会自动回退到合理默认值：

T
title · 必填

缺失时自动取正文中第一个 # 一级标题。

D
date · 可空

默认 today，缺失时回退到文件 mtime。

S
description · 可空

缺失时自动取正文前 200 字符（去除 Markdown 标记）。

C
category · 可空

缺失时归入"未分类"。

#
tags · 可空

数组，可省略；v2.0 修复了中文 tag 的 URL slug 二次编码问题。

⏱
readingTime

200 字/分钟，CJK 按字符，英文按词数加权，在 utils/readingTime.ts 计算。
